{{- /* The comments block, rendered at the very foot of an article (page.html). Renders nothing at all on a site with the feature off, or on a page that opted out with `comments: false` in front matter. `ne .Params.comments false` and not `| default true`: in Hugo `false` is an empty value, so `default` would hand `true` straight back to the page that asked for silence. The widget is NOT started here. `auto-init` is left off entirely because the engine's bundle is injected by modules/comments.js on click — the element upgrades and starts itself the moment the script lands, so a second switch would only be one more thing to keep in step. Attributes, and why each one is there: no-fonts the engine otherwise pulls Source Sans Pro from its own origin and argues with the page's Inter. theme light/dark, printed from the palette the server chose; modules/comments.js keeps it in step afterwards. It is the ONLY attribute that may change at run time — `lang` and `css-override` reinitialise the widget and throw away a half-written comment. page-id the thread's identity. Stated explicitly from RelPermalink rather than left to the engine's `location.pathname`, so a reader arriving at the same page without its trailing slash lands in the same thread. `lang` is deliberately absent: the engine reads and ships every translation in its binary. data-pagefind-ignore: comments are not the article, and a search for a word someone used in a reply must not answer with the guide. */ -}} {{- $c := partialCached "comments/cfg.html" . .Language.Lang -}} {{- if and $c.enable (ne .Params.comments false) -}}
