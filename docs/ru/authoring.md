# Как писать гайд

Гайд — это **папка-бандл**: каталог с `index.md` и, если в тексте есть живые
иллюстрации, соседней папкой `widgets/`. Эта страница — контракт на то, как его
написать: front matter, шорткоды, код, ссылки, диаграммы, виджеты, обложки,
переводы и голос.

## Начни с архетипа {#archetype}

```sh
hugo new content howto/my-guide --kind guides            # одиночный гайд
hugo new content howto/handbook/my-guide --kind guides   # часть серии «handbook»
```

Получишь каркас бандла — `index.md` с заполненными основными полями и заготовку
`widgets/w-example/widget.js`. **В пути нет `/index.md`**: передавай папку
бандла, иначе Hugo переключится в режим одиночного файла и молча не скопирует
соседние файлы архетипа. Папка без `widgets/` — первый признак этой ошибки.

Первый сегмент пути должен быть секцией из `params.rubricSections` — именно это
делает страницу гайдом (две панели, кикер, чипы меты, оглавление, мост серии),
а не обычной колонкой. Гайд, положенный на одну папку глубже, — **часть
серии**, см. [Серии](#series-and-weight).

## Front matter {#front-matter}

```yaml
title: "Значения и layout: как Go-значение лежит в памяти"
slug: memory-1-layout        # фиксирует URL (…/memory-1-layout/)
date: 2026-03-07             # лента, RSS, sitemap — в тексте статьи не появляется
description: "Одно предложение — для ленты, поиска и meta."
lead: "Лид-абзац (может быть длиннее description)."
weight: 1                    # порядок части внутри серии; у одиночного гайда — опустить
tags: [memory, layout, unsafe]
mins: 12                     # чип «~12 мин» — руками, а не .ReadingTime
version: "go1.26"            # свободный чип «проверено на»; без него — versionDefault
rail_title: "Layout"         # необязательно: 2–4 слова для левой панели и миникарты
related: []                  # для одиночных гайдов: 3–5 контент-путей для панели «ещё по теме»
```

| Поле | Обязательно | Что делает |
|---|---|---|
| `title` | да | Режется по первому `": "` на `<h1>` и `.sub`; переопределяется через `sub:`, а заголовок без `": "` остаётся в одну строку. |
| `slug` | да | Фиксирует красивый URL; после публикации не меняй — и держи **одинаковым во всех переводах** (см. [Перевод гайда](#translating-a-guide)). |
| `date` | да | Порядок ленты и RSS, печатается на карточке в ленте. **В тексте статьи не появляется никогда.** |
| `description` | да | Карточка ленты, результат поиска, `og:description`, `<description>` в RSS. Пиши его для страницы выдачи, а не как второй заголовок: 70–160 символов и **без markdown** — это обычный атрибут, строка едет дословно, поэтому бэктик и напечатается бэктиком (линтер об этом скажет). А вот `lead` — это markdown: его рендерит и страница, и фолбэк описания. Архетип кладёт сюда **сентинел** `TODO`, и `params.seo.lint` роняет сборку, пока он на месте: гайд не имеет права уехать в прод, описывая себя как TODO. |
| `lastmod` | при правке | Дата последнего изменения опубликованного гайда, напр. `2026-09-22`. Именно её печатают `dateModified`, `article:modified_time` и sitemap — других способов узнать, что гайд уже не тот, что год назад, у поисковика нет. Штатный фронтматтер Hugo, `enableGitInfo` не нужен. |
| `titleSuffix` | опционально | Переопределяет, заканчивается ли `<title>` на ` — <сайт>`. Обычно имя сайта дописывается, только пока строка укладывается в `params.seo.titleMax`; `false` убирает его со страницы, которая укладывается, `true` оставляет на той, что нет. |
| `noindex` | опционально | `true` убирает страницу из поиска: `noindex, follow` в robots-теге и никакой записи в `sitemap.xml`. Для страниц, которые существуют не затем, чтобы их находили. |
| `lead` | наследие | Вводный абзац в одну штуку — остался для гайдов, написанных до разделителя `<!--more-->` (ниже). Он же запасной вариант для `og:description`. |
| `weight` | для частей серии | Порядок части внутри папки серии. См. [Серии](#series-and-weight). |
| `tags` | желательно | Чипы, ведущие на страницу тегов, на якорь `#<tag>`. Держи **одинаковыми во всех переводах**. |
| `mins` | желательно | Чип времени чтения, сумма длительности на странице рубрики и шкала моста серии; без него — `.ReadingTime`. |
| `version` | опционально | Свободный чип «проверено на», печатается как есть (`go1.26`, `PostgreSQL 17`). Без него — `params.versionDefault`; нет ни того, ни другого ⇒ чипа нет. |
| `arch` | опционально | Дописывается к чипу версии через `·`, например `64-бит`. |
| `interactive` | опционально | Добавляет третий чип меты — перечень того, что на странице интерактивно. |
| `interactive_label` | опционально | Подпись этого чипа; по умолчанию — i18n-ключ `meta_interactive`. |
| `rail_title` | опционально | Короткое имя для левой панели, миникарты и моста серии. По умолчанию — заголовок до первого `:`. |
| `linkTitle` | опционально | Короткий заголовок для списка частей на странице рубрики. `<h1>` и `<title>` не трогает. |
| `related` | только одиночные | 3–5 **контент-путей** (`inside/anatomy/palette-is-a-file`, а не URL) для панели «ещё по теме». Если не указано ничего — или ничего не разрешается в страницу, — левая панель не рендерится вовсе. У гайда в серии игнорируется — там панель показывает части. |
| `placeholder` | опционально | См. [Заглушки](#placeholders). |
| `og_image`, `og_style` | опционально | См. [Обложки (OG-картинки)](#covers-og-images). |
| `cover` | опционально | Собственная картинка страницы — баннер в ленте и картинка шаринга. См. [Обложки (OG-картинки)](#covers-og-images). |
| `sub` | опционально | Переопределяет автоматическое деление `title`. |
| `intro` | опционально | Markdown между чипами меты и оглавлением. |
| `foot` | опционально | Markdown в самом низу, под мостом серии. |
| `mascot` | только одиночные | Рисует партиал сайта `_partials/page/mascot.html` в начале страницы, передавая ему это значение как контекст. Нет такого партиала у сайта ⇒ ничего не рисуется. |
| `toc_labels` | устарело | Карта «id заголовка → короткая подпись» для обоих оглавлений: `toc_labels: {two-fields: "Два поля"}`. Требует знать id заголовка, поэтому вместо неё пиши `{short="…"}` у самого заголовка (см. [Короткие имена в оглавлении](#short-toc-entries)). Всё ещё читается — страницы, уже написанные с ней, не трогай. |
| `toc_inline` | опционально | Оставляет блок оглавления в тексте и на широких экранах, где его обычно заменяет правая панель. Панель при этом скрыта целиком — вместе с миникартой, — пока блок на экране, и проявляется, когда его пролистали. Для длинного обзора, где блок — карта, которую читают до статьи; обычному гайду два оглавления ни к чему. |
| `lead_deck` | опционально | Набирает лид как вводку-дек (19px, тише тоном), а не как обычную прозу. Для вступления, которое представляет статью; если лид просто её начинает — не включай. |
| `draft` | опционально | Штатный Hugo. Архетип ставит `draft: true`. |

`kicker:` и `headline:` читаются только на **не-гайдовых** страницах (о сайте,
роадмап, `/tags/`); у гайда кикер собирается из рубрики и серии, и задавать их
бессмысленно.

### Лид и `<!--more-->`

Поставь строку `<!--more-->` после вводной прозы гайда:

```markdown
Вводные абзацы, которые держатся сами по себе и продают клик.

<!--more-->

## Первый раздел
```

Разделитель делает две работы. В статье он отделяет вводную часть от тела —
проза над ним и есть открытие статьи, оформленное как обычный текст. В ленте
он становится превью, если сайт включил `params.home.feedPreview = "summary"`;
гайд **без** разделителя продолжает показывать свой `description`, потому что
иначе Hugo синтезировал бы автосаммари с обрывом на полуслове. Поэтому
заканчивай лид на крючке, а не посреди примера.

### Короткие имена в оглавлении {#short-toc-entries}

Заголовок раздела может позволить себе двоеточие и придаточное — оглавление не
может: в ширину панели оно переносится на три строки. Дай заголовку короткое
имя для списков через `{short="…"}`:

```markdown
## Рантайм: аллокации, метки в трейсбеках, таймеры {short="Рантайм: аллокации и таймеры"}

### Подраздел, чьё название длиннее панели {short="Подразделы"}
```

Работает для `h2` и `h3`, и читают его оба оглавления — блок внутри текста и
правая панель. Сам заголовок, его `id` и якорная ссылка не меняются: короткое
имя живёт только в списках, поэтому знать, что Hugo сделал из названия, не
нужно. Заголовок без атрибута попадает в списки как написан.

Это штатный атрибут заголовка Goldmark, тот же механизм, что и `{#custom-id}`,
и живёт в тех же скобках: `## Заголовок {#custom-id short="Короткий"}`.

### Серии {#series-and-weight}

Серия — это **папка**, под-секция своей рубрики. Членство — то, где лежит
бандл, и ничего больше:

```
content/howto/
  handbook/                 ← серия
    _index.md               ← метаданные серии (ниже)
    get-started/index.md    ← часть, weight: 1
    first-guide/index.md    ← часть, weight: 2
  build-magic/index.md      ← одиночный гайд (прямой ребёнок рубрики)
  standalone/               ← необязательный контейнер одиночных гайдов (ниже)
    _index.md               ← params.standalone: true
    build-magic/index.md    ← одиночный гайд, идентичный верхнему
```

`weight` во front matter части — её порядок внутри серии. Кикер «часть N из M»,
левая панель и нижний мост (сегменты по `mins`, «осталось ~N мин») выводятся из
папки, на сборке. Добавить часть — положить бандл в папку серии; перенести гайд
в серию или из неё — это `mv`. Серия из одной части рендерится как одиночный
гайд: механика включается начиная с двух.

Каждая серия рендерит **лендинг** (`/<рубрика>/<серия>/`): заголовок, тэглайн,
лид, тело `_index.md` как эпиграф, список частей и кнопку «начать серию». Лид —
это `lead`, если он есть, иначе `description`; тот же раздел труда, что у
рубрики: `lead` написан для страницы и может быть сколь угодно длинным, а у
`description` есть вторая работа — meta-тег и карточка, где длинная строка
обрезается на полуслове.
Страница рубрики показывает ту же серию блоком с якорем
(`/<рубрика>/#<серия>`); серия, анонсированная `_index.md` без частей,
появляется там тизером «готовится», а её лендинг рендерит анонс. Каркас
`_index.md` создаёт архетип:

```sh
hugo new content howto/handbook/_index.md --kind series
```

```yaml
title: "Память"             # имя серии: кикеры, блок на рубрике и лендинг
description: "Одна строка — meta-тег и карточка лендинга."
lead: "Абзац, который показывает лендинг (необязательно; может быть длиннее)."
weight: 10                  # порядок серий на странице рубрики
params:
  label: "память"           # короткое имя в кикерах (иначе — title в нижнем регистре)
  tagline: "3 части, от байта до GC"   # необязательная строка рядом с «серия ·»
```

### Одиночные гайды и контейнеры {#standalone}

Одиночный гайд — прямой ребёнок своей рубрики: без папки серии и без `weight`.
Когда одиночных становится много и папки серий тонут среди них, сложите их в
**контейнер** — под-секцию, чей `_index.md` состоит из одного маркера. Обе
формы равноправны, так что переезжать можно по одному `mv` за раз:

```yaml
title: "Standalone"         # нигде не рендерится
params:
  standalone: true          # «мои дети — одиночные гайды, я не серия»
build:
  render: never             # у контейнера нет собственной страницы
  list: local               # виден шаблонам рубрики, невидим глобально
```

Контейнер держит **только leaf-бандлы** — серию внутрь него класть нельзя. На
многоязычном сайте маркерный `_index.md` обязан существовать **в каждом языке**
(`_index.md` + `_index.ru.md`), иначе дерево другого языка сочтёт папку серией.

Гайдам **вне рубрик** заводится собственная секция верхнего уровня, указанная в
`params.extraGuideSections` (см. [params.md](params.md)): её страницы попадают
в ленту, поиск и RSS с полным статейным layout'ом, а кикер берёт `label` из
`_index.md` секции — но рубрикой она не считается (ни карточки на главной, ни
строки в 404).

### Заглушки {#placeholders}

Ненаписанный гайд можно выпустить заглушкой: полный front matter (лента живёт с
него), тело — одна строка, и `placeholder: true`. Такой гайд считается в ленте,
в облаке тегов и в структуре серии («часть N из M»), но **не попадает ни в RSS,
ни в поисковый индекс**. Дописал текст — снял флаг.

## Выделения в тексте {#emphasis}

Цитата `>` — это чужие слова. То, что говоришь своим голосом, получает
собственный блок — и пишется обычным Markdown, так что тот же исходник без
плагинов читается в Obsidian (парная тема рисует все четыре):

| Блок | Markdown | Для чего | Как часто |
|---|---|---|---|
| Тезис | `>> текст` | вывод раздела, одна-три фразы | не больше одного на `h2` |
| Ремарка | `> [!aside]` | «к слову», аналогия, оговорка — на тон тише | по делу |
| Итог | `> [!recap] метка` | чекпоинт в конце раздела: «теперь ты можешь …» | не больше одного на `h2`, не рядом с тезисом |
| Эпиграф | `> [!epigraph] источник` | цитата на пороге | по одному на порог: гайд, раздел, страница серии |
| Цитата | `> текст` | чужие слова, и только они | по делу |

```md
>> После `append` все старые заголовки на тот же массив — под подозрением.

>> Тезис из двух абзацев: пустая строка между ними — тоже `>>`.
>>
>> Второй абзац.

> [!aside]
> К слову, заголовок передаётся по значению.

> [!recap] чекпоинт
> Теперь ты скажешь, может ли функция нарастить твой слайс на месте.

> [!epigraph] Роб Пайк, [Go Proverbs](https://go-proverbs.github.io/), 2015
> Clear is better than clever.
```

Тезис набран прямым шрифтом и цветом текста, с акцентной чертой там же, где
черта у цитаты; цитата остаётся курсивной и на тон тише. У ремарки черты нет
вовсе — только отступ и шрифт мельче и тише. Итог — короткая акцентная черта и
моно-метка над обычным абзацем (без метки — i18n `recap`). Эпиграф —
единственный блок, набранный курсивом целиком: он сдвинут вправо, источник —
моно-строкой, тире перед источником тема ставит сама. У всех одна вертикаль:
знак на краю колонки, текст на отступе списка, поэтому цитата и тезис на одной
странице стоят ровно друг под другом.

У разметки есть правила, и сборка предупреждает (строгая — падает), если одно
из них нарушено:

- Текст `[!aside]`, `[!recap]` и `[!epigraph]` начинается со **следующей**
  строки. Строка маркера — это метка итога или источник эпиграфа; у ремарки
  она бы потерялась.
- Тип — только латинские буквы, без знака сворачивания `+`/`-`. Неизвестный
  тип (`[!asdie]`) рисуется обычной цитатой.
- Не смешивай `>` и `>>` в одной цитате: цитата, в которой нет ничего, кроме
  одной вложенной, — это тезис, а всё, что стоит рядом, оставляет её цитатой.
  В Obsidian ставь маркер на каждой строке — ленивая строка продолжения там
  теряет уровень.
- Атрибуты работают, как у любого блока: `{#append-rule}` на строке после
  тезиса даёт ему якорь для ссылки.
- Эпиграф, открывающий гайд, стоит **над** лидом: пиши его первым и оставь
  разделитель `<!--more-->` (см. «Лид и `<!--more-->`» выше). Страница вынимает
  его из лида, ленты и meta description. С устаревшим `lead:` в front matter он
  встанет под лидом.

Выделения внутри строки — маленькие. **Жирный** (вес 600) — термин в момент
определения или зачин абзаца; *курсив* — одно-три слова интонации, настоящий
курсив Inter, который скачивается, только если на странице он есть. Главной
мысли в одну фразу больше не нужен `callout type="key"`: для этого есть `>>`.

## Шорткоды {#shortcodes}

Одиннадцать: семь для любого гайда и ещё четыре — для сайта с рассылкой.

### callout — `{{</* callout type="trap" */>}}` {#callout}

Пять типов: `key` (главная мысль), `trap` (ловушка), `note` (историческая
сноска), `internals` (под капотом), `warn` (внимание). Подпись берётся из i18n
(`callout_key`, `callout_trap`, `callout_note`, `callout_internals`,
`callout_warn`), переопределяется через `label=`. Тело — Markdown. По умолчанию
`type` — `note`.
Коллаут — это врезка, без которой текст обойдётся. Главной мысли в одну фразу
место в потоке, тезисом (`>>`, см. [Выделения в тексте](#emphasis)); `key` —
для вывода на несколько абзацев или чек-листа.

```md
{{</* callout type="key" */>}}
Заголовок слайса — три слова: указатель, длина, ёмкость.
{{</* /callout */>}}
```

### fold — `{{</* fold icon="video" title="…" */>}}` {#fold}

Тихая сворачиваемая врезка. В свёрнутом виде — одна строка: значок, заголовок
и переключатель «Подробнее ⌄», без рамки и фона, так что читается как часть
текста; клик плавно раскрывает панель по высоте. Годится для отступления,
которое читатель может взять или пропустить: видео-версия, оговорка, полный
листинг. Тело — Markdown, а `title=` — инлайновый Markdown, поэтому ссылка в
заголовке работает и по клику не сворачивает панель.

**Тихим должно быть свёрнутое состояние, а не раскрытое.** Раскрытая панель
набрана прозой — тем же кеглем и цветом, что статья вокруг: клик по
«Развернуть» и есть согласие читателя читать, а мелкий приглушённый текст в
ответ на него — наказание за клик. «Это вставка» говорит не типографика, а
структура: строка-заголовок сверху, тонкий рельс слева (он растёт из значка и
единственный переживает прокрутку — за первым экраном заголовок уже уехал) и,
у длинных катов, строка-выход внизу.

**Два регистра, выбираются сами по длине тела.** Короткий кат (до ~900
символов) остаётся сноской: тихий заголовок, без строки-выхода. Длинный
становится необязательной главой — заголовок читательским кеглем, свой воздух
вокруг блока, ускоренное раскрытие (на четырёх экранах прежние 0.2 с читались
как рывок) и кнопка «Свернуть» в конце, которая сворачивает панель и
возвращает к заголовку, если тот уже уехал за верх экрана — иначе схлопывание
с конца телепортирует читателя в случайное место статьи. Регистр берётся из
того, что написано, а не спрашивается у автора; `size=` переопределяет его
вручную.

Рельс — тоже выход: клик по нему сворачивает кат, наведение подсвечивает и
линию, и кнопку внизу. На любой прокрутке длинной панели выход оказывается на
расстоянии движения мыши влево. Только для мыши: на тач-экране полоса вдоль
левого поля прокручиваемой страницы ловила бы случайные тапы, а ховера,
который бы о ней предупредил, там нет.

На телефоне (≤560px) эта строка становится двумя: заголовок занимает всю
ширину, а переключатель уезжает под него — чтобы длинный заголовок не
сжимался в колонку по три слова из-за стоящей рядом подписи.

```md
{{</* fold icon="video" title="Есть также [видео-версия](https://youtu.be/…)." */>}}
Сначала посмотрите, потом прочитайте для закрепления — что-то нагляднее на
экране, что-то лучше усваивается текстом.
{{</* /fold */>}}
```

| Параметр | Значение |
|---|---|
| `title=` | строка-заголовок, инлайновый Markdown (обязателен) |
| `icon=` | ведущий значок из набора ниже; по умолчанию `info`, `none` — убрать |
| `more=` | подпись в свёрнутом виде (по умолчанию `Подробнее`) |
| `less=` | подпись в раскрытом виде (по умолчанию `Свернуть`) |
| `open=` | `true` — отрендерить сразу раскрытым |
| `size=` | `note` или `section` — переопределить автоматический регистр |

Значки: `video` · `info` · `tip` · `book` · `code` · `terminal` · `warning` ·
`star` · `link` · `note`.

Панель анимирует высоту — настоящий выезд, не фейд — через `interpolate-size`
на `:root` (задан в `00-tokens.css`); где браузер его не поддерживает, панель
раскрывается мгновенно. Подписи по умолчанию русские; переопределяются в
вызове.

### term — `{{</* term "mcache" */>}}` {#term}

Слово в тексте, за которым стоит полноценная карточка-определение: наведение
раскрывает её, клик закрепляет — можно спокойно читать и уйти по ссылке, Escape
закрывает. Тело — Markdown: жирный, инлайн-код, списки, ссылки, блоки кода,
картинки.

```md
У каждого P есть свой {{</* term "mcache" */>}}
Пер-P кэш мелких объектов. Аллокация из него идёт **без единого атомика** —
быстрый путь не трогает разделяемое состояние.
{{</* /term */>}}, и попадание в него — самый дешёвый путь аллокации.
```

| Параметр | Смысл |
|---|---|
| *позиционный 0* или `word=` | слово так, как оно читается в предложении (обязателен) |
| `title=` | шапка карточки, когда она отличается от слова; по умолчанию — само слово |
| `kind=` | свободный текст моно-ярлыка («структура рантайма», «железо»); без него ярлыка нет |
| `color=` | `accent` (по умолчанию — цвет бренда) \| `green` \| `copper` \| `blue` \| `gold` \| `red` |
| `href=` | адрес необязательной ссылки «читать подробнее»; внутренний путь разрешается в пермалинк |
| `more=` | текст этой ссылки (по умолчанию — i18n-ключ `term_more`) |

**Hugo не разрешает смешивать позиционные и именованные параметры.** Поэтому либо
короткая форма `{{</* term "mcache" */>}}`, либо полностью именованная — как
только понадобился `title=` или любой другой параметр, слово переезжает в
`word=`:

```md
данные лежат в {{</* term word="кэшах ядра" title="Кэш процессора"
                     kind="железо" color="green"
                     href="/inside/caches/" more="Разбор: иерархия памяти" */>}}
Три уровня — L1, L2, L3. Чем ближе к ядру, тем меньше и быстрее.
{{</* /term */>}}, а не в оперативке.
```

#### Схема или картинка в карточке

Тело рендерится как блочный Markdown — тем же конвейером, что и статья, — поэтому
в определение ложится всё, что разрешено в гайде, включая сырой блочный HTML.
Схема — это обычная разметка диаграмм темы (см. [Диаграммы](#diagrams)), завёрнутая
в `{{</* raw */>}}`; никакого параметра шорткода для этого не нужно:

```md
слайс — это {{</* term word="заголовок из трёх слов" kind="раскладка" */>}}
Три машинных слова, всегда в этом порядке:

{{</* raw */>}}
<div class="header">
  <div class="header-word ptr"><span class="wk">ptr</span><span class="wv">0x1040</span></div>
  <div class="header-word"><span class="wk">len</span><span class="wv">4096</span></div>
</div>
{{</* /raw */>}}

Переслайсивание двигает `len`; `ptr` съезжает только при росте за `cap`.
{{</* /term */>}}, а не растущий массив.
```

Картинка кладётся так же — обычной Markdown-картинкой; параметра `img=` нет, и он
не нужен. Она проходит через тот же render hook, что и картинки в статье: имя
ищется сначала в бандле страницы, потом в `assets/img/`, размеры проставляются
автоматически, `alt` берётся из Markdown, а заголовок в кавычках становится
подписью — ровно как в прозе:

```md
аллокатор выдаёт {{</* term word="спан" kind="структура рантайма" */>}}
Прогон страниц, нарезанный на объекты одного size-класса.

![как нарезан спан](span.png "8 КиБ, один size-класс")

Всё остальное об объекте решает его класс.
{{</* /term */>}}, а не отдельный объект.
```

Четыре способа сломать это тихо:

- **Сырой HTML с пустой строкой внутри разрежется пополам — бери
  `{{</* raw */>}}`.** Пустая строка закрывает HTML-блок Markdown, и всё после
  неё парсится уже как Markdown: строки с отступом (а вложенные `<div>` пишут
  именно с отступом) возвращаются блоком кода с экранированными тегами, и сборка
  не скажет об этом ни слова. Шорткод `raw` забирает тело целиком — поэтому
  пример выше написан через него. Инлайновому HTML без пустых строк обёртка не
  нужна.
- **Карточка узкая.** Примерно 360px контента у обычного определения, 420px —
  если внутри список, таблица, картинка или код, и 480px — если схема или
  картинка с подписью: карточка сама выбирает ступень по своему содержимому. На
  телефоне это нижний лист шириной с экран, то есть обычно *меньше*. Всё, что
  шире, скроллится вбок внутри карточки, и на macOS полосы прокрутки, которая бы
  об этом сказала, не будет. Рисуй под ~480px или собирай схему из переносящихся
  рядов (`.mem-row`, `.byte-strip`), чтобы она перетекала.
- **У SVG должны быть `width` и `height` на корневом элементе.** Render hook
  проставляет размеры только растру, поэтому у SVG с одним `viewBox` нечего
  зарезервировать: он открывается в карточке в разы меньше нарисованного, а
  поповер позиционируется по этой неверной высоте. Растр безопасен — его размеры
  уже в разметке.
- **Карточка — это `role="dialog"`.** Скринридер читает её содержимое целиком,
  поэтому у картинки должен быть настоящий `alt` (то, что в `![alt]`, а не имя
  файла), а у декоративной схемы — `aria-hidden="true"` на внешнем элементе.

Ещё две вещи, которые стоит знать:

- **Карточка рисуется не там, где ты её написал.** Абзац не может по правилам
  HTML содержать `<pre>` или `<div>` — парсер закроет его и разорвёт текст, — и
  поэтому шорткод оставляет в прозе инлайн-ссылку, а карточки собираются и
  выводятся после тела статьи. С выключенным JavaScript они там и видны, простым
  списком «Определения», и каждое слово ведёт к своему. Это и есть весь сценарий
  без JS — и то же самое уходит в печать.
- **Повторять термин ничего не стоит.** Идентификатор карточки — хеш от слова и
  определения, поэтому одно и то же слово с одним и тем же определением, взятое
  пять раз, делит одну карточку, и каждое упоминание её открывает. Изменишь
  определение — появится вторая карточка; если это не то, чего ты хотел, держи
  формулировку одинаковой.

### widget — `{{</* widget id="w-x" */>}}` {#widget}

Три формы (см. [Виджеты](#widgets)):

```md
{{</* widget id="w-escape" cap="Поиграй" note="— двигай слайдер, смотри на кучу" */>}}
```
- **самозакрытый, с `id`**: рендерит подпись и mount `.w-root`. Если у бандла
  есть ресурс страницы `widgets/w-escape/figure.html`, его содержимое заполняет
  mount как вид без JS; если такого ресурса нет, mount стартует пустым, и его
  заполнит `widgets/w-escape/widget.js`, как только сработает. `cap` перебивает
  подпись по умолчанию (i18n-ключ `widget_cap`), `note` — приглушённая ремарка
  после неё.
- **с `id` и телом внутри**: внутренний HTML — вид без JS вместо ресурса
  `figure.html`, для фолбэка, который короче держать рядом с шорткодом, чем в
  отдельном файле.
- **сырой** (без `id`, только тело): внутренний HTML кладётся прямо в фигуру.

`bare="true"` снимает рамку: ни бордера, ни отступов, подпись скрыта от глаз,
но остаётся доступным именем фигуры. Для фигуры, которая должна читаться как
часть текста — «живая» фраза, ползунок под абзацем.

### bars — `{{</* bars */>}}` + таблица {#bars-shortcode}

Горизонтальные полосы из Markdown-таблицы: одна серия, группы или части одной
полосы. См. [Данные в тексте → bars](#bars).

### chart — `{{</* chart */>}}` + таблица или `{{</* chart src="…" /*/>}}` {#chart-shortcode}

Линейный график из одних данных — таблица в теле или YAML-файл в бандле. См.
[Данные в тексте → chart](#chart).

### spanmap — `{{</* spanmap bits="111100" size="24" */>}}` {#spanmap-shortcode}

Слоты спана и его битовая карта, всё выводится из битов. См.
[Данные в тексте → spanmap](#spanmap).

### bigcard — `{{</* bigcard href="/playground/" k="Песочница →" t="…" s="…" */>}}` {#bigcard}

Ссылка-карточка: `k` — кикер, `t` — заголовок, `s` — подзаголовок. Внутренний
`href` разрешается в пермалинк (и потому переживает смену слага), внешний
проходит как есть.

### raw — `{{</* raw */>}}…{{</* /raw */>}}` {#raw}

Отдаёт своё содержимое HTML'ем как есть — для рукописных диаграмм ниже. В отличие
от голого HTML-блока в Markdown, шорткод захватывает тело целиком, поэтому
пустая строка внутри не обрывает блок — на верхнем уровне. Внутри
`{{</* term */>}}` тело — это Markdown, который рендерится уже после шорткода, и
там пустая строка в HTML по-прежнему обрывает блок. Прежде чем браться за сырой
HTML, загляни в [Данные в тексте](#data): в Obsidian сырой HTML — стена исходника.

### run — `{{</* run sandbox="go1.26.4" */>}}…{{</* /run */>}}` {#run}

Делает блок кода над собой запускаемым и несёт под ним его вывод. Описан вместе
с остальной обвязкой в разделе [Запускаемые сниппеты](#runnable).

### roadmap — `{{</* roadmap */>}}` {#roadmap}

Рисует блоки роадмапа — карточки «в работе», очередь, правила — из данных сайта:
либо плоский `data/roadmap.toml`, либо, на многоязычном сайте,
`data/roadmap/<lang>.toml` (так сделано в демо). Те же данные питают полосу «в
работе» на главной. Пример — `roadmap.md` в демо.

### newsletter, newsletter-cta, newsletter-inline — блоки подписки {#newsletter}

Только на сайте с рассылкой (`params.newsletter.enable`, по умолчанию
выключена). На сайте без неё они **валят сборку**, а не молча рендерят пустоту:
исчезнувший без единого слова шорткод — это вопрос, на который со страницы не
ответить. Тот, кто выключил рубильник осознанно и хочет сохранить разметку,
добавляет `ignoreLogs = ['newsletter-disabled']` — и блоки снова замолкают:
[newsletter.md](newsletter.md#шорткоды).

```md
{{</* newsletter label="серия · продолжение" dismiss="sched-1" */>}}
Это первая статья серии. Оставьте почту — пришлю продолжение.
{{</* /newsletter */>}}
```

`newsletter` — тихий срединный блок (с `dismiss=` читатель закрывает его
насовсем), `newsletter-cta` — карточка побольше в конце статьи,
`newsletter-inline` — голая форма для страницы, написанной прозой. Все тексты
твои: параметры шорткода → front matter страницы `newsletterCta` → дефолты i18n
темы. Ещё два — `newsletter-archive` и `newsletter-letter-example` — относятся к
странице подписки и появляются там, где написаны. Всё это вместе с конфигом:
[newsletter.md](newsletter.md).

## Блоки кода {#code-blocks}

Обычные fenced-блоки, подсветка — Chroma на сборке, перекрашенный в палитру
темы. Подсвечиваются языки

```
go  json  yaml/yml  bash/sh/shell/zsh  c  css  html  xml
javascript/js  typescript/ts  sql  diff  python/py
```

а **голый забор**, ` ```text ` и ` ```txt ` — это плоская форма: она рендерится
как `<code class="nohl">`, и именно она нужна выводу шелла, трейсу или gc-логу.
Всё прочее тоже уходит в плоское: это allowlist, а не «всё, что Chroma умеет
разобрать», потому что язык, чьи главные токены в этой палитре без цвета,
читается хуже подсвеченным наполовину, чем плоским. `toml` и `asm` были
проверены и отклонены ровно по этому признаку — прежде чем добавлять свой,
загляните в комментарий `layouts/_markup/render-codeblock.html`.

Цвет означает одно и то же в любом языке: янтарный — ключевое слово, синий —
тип или структурное имя (ключ JSON, тег HTML), зелёный — вызываемое, медный —
число, отдельный тон для строк, приглушённый курсив для комментариев.

Два атрибута забора:

````md
```go {label="runtime/malloc.go (упрощено)" hl_lines=[2]}
func mallocgc(size uintptr) unsafe.Pointer { … }
```
````

- `{label="…"}` — подпись файла над блоком. Работает для любого языка.
- `{hl_lines=[2]}` — подсветка строк; диапазоны передаются строками:
  `hl_lines=[2,"5-7"]`. Только в подсвеченных блоках (это опция Chroma, плоскому
  забору нечего размечать).

У каждого листинга есть **кнопка копирования** — писать ничего не нужно,
включать тоже. Пока блок читают, её нет: она появляется в правом верхнем углу,
когда в листинг заходит курсор или до него добирается клавиатура. Копирует код
без хвостового перевода строки — вставленная в шелл команда предлагает себя, а
не запускается. У запускаемого сниппета в режиме правки берёт то, что набрал
читатель, а не исходный текст. На тач-экране проявлять её нечем, поэтому там она
видна всегда, на тон тише. Подписи — ключи `js_copy_*` в `i18n/`, стили —
`assets/css/27-code-copy.css`.

### Запускаемые сниппеты {#runnable}

Блок кода становится запускаемым — и редактируемым, — если сразу за ним идёт
шорткод `{{</* run */>}}`. Запускает [codapi](https://github.com/nalgeon/codapi-js).
Песочница указывается один раз на весь сайт:

```toml
[params.codapi]
url = "https://run.example.com/v1"
```

— и гайд про неё больше не знает:

````md
```go
func main() { fmt.Println("hi") }
```
{{</* run sandbox="go1.26.4" */>}}
hi
{{</* /run */>}}
````

Сам codapi тема везёт с собой (`assets/vendor/codapi/`, MIT) и подключает только
на тех страницах, где есть сниппет: версия зафиксирована, файл идёт с твоего
домена, с fingerprint и `integrity`, как и весь остальной код. `sandbox=` без
`params.codapi.url` **роняет сборку**: кнопка Run, ведущая в никуда, хуже
упавшей сборки. Поднять или откатить версию можно, положив свой
`assets/vendor/codapi/snippet.js` поверх файла темы.

Своего сервера у отдельного сниппета не бывает: codapi берёт адрес из
единственной глобальной настройки в момент запроса и на сам элемент не смотрит —
так что `url=` у шорткода выглядел бы главным, а не менял бы ничего. Поэтому он
роняет сборку, а не молчит.

#### Блок вывода {#run-output}

Тело шорткода — **вывод, записанный автором**, и он на странице с самого начала:
большинство читателей Run не нажмёт никогда, так что это основной вид, а не
запасной. Рисуется транскриптом терминала, первая строка — приглашение
`$ go run main.go`, оно же тоггл и носитель статуса. В свёрнутом виде остаётся
только приглашение, и это читается само: «команда отработала, вывод убран».

По кнопке Run результат **заменяет** записанный вывод на месте. Иначе codapi
нарисовал бы второй, почти такой же блок прямо над авторским, и читателю пришлось
бы разбираться, где чей; здесь вывод на странице всегда ровно один. Чей именно —
говорит приписка в конце строки приглашения: «пример» → «запуск · 128 ms»
(зелёным) или «ошибка · 89 ms» (медью), а **вернуть пример** возвращает авторский.
Тело берётся **дословно**, поэтому пиши его от левого края: у вывода программы
свои отступы.

Иначе это число врал бы кеш перед раннером. Ответ из кеша несёт длительность
**исходного** прогона, поэтому повторное нажатие на неизменённом коде приходит
в десять раз быстрее и всё равно показывает время первого запуска — одно и то
же число, сколько ни жми, что читается как зависший виджет, а не как быстрый
кеш. Поэтому тема сама измеряет ожидание всякий раз, когда ответ приходит
быстрее заявленной в нём длительности: сервер не может ответить за меньшее
время, чем занял прогон, — значит, ответ отдали из кеша, и приписка показывает
то, что читатель действительно прождал. У настоящего прогона остаётся цифра
сервера, и для гайда про производительность она лучше: в ней нет сети. Ничто из
этого не завязано ни на конкретный кеш, ни на его заголовки; в событии `result`
самого сниппета у такого ответа стоит `cached: true` — на случай, если сайт
захочет сказать об этом вслух.

| параметр | |
|---|---|
| `sandbox=` | id песочницы codapi. Обязателен — кроме прогона, за которым песочницы нет (см. ниже). |
| `command=` | команда codapi. По умолчанию `run`. |
| `editor=` | `basic` (редактируемый) · `off` (листинг только для чтения). По умолчанию `basic`. |
| `cmd=` | команда в строке приглашения. По умолчанию — читаемая замена по sandbox+command (`go run main.go`, `go test`, `go test -bench=.`). |
| `note=` | короткая подпись, ставится шелловым комментарием после команды: `# stderr — полная трасса`. Именно она говорит о свёрнутом блоке, что внутри. |
| `open=` | `false` — блок приезжает свёрнутым. По умолчанию раскрыт. |
| `error=` | `true`, если записанный вывод САМ является ошибкой — тогда он сразу читается в «провальном» цвете. |

Самозакрывающаяся форма — `{{</* run sandbox="go1.26.4" /*/>}}` — блок приезжает
скрытым и появляется с первым результатом читателя. **Без** `sandbox=` блок
рисуется один, без кнопки Run и без единого элемента управления: для вывода,
снятого на машине, до которой читателю не добраться (другая версия Go, другое
число ядер). Там нужен `cmd=` — выводить приглашение не из чего.

Ещё пробрасываются в `<codapi-snippet>`, если заданы: `url`, `template`, `files`,
`id`, `depends-on`, `actions`, `output-mode`, `engine`, `selector`, `init-delay`,
`status-running`, `status-done`, `status-failed`. Последние три — собственные
статусы codapi (`Running…` / `✓ Done` / `✗ Failed`), по умолчанию оставлены
английскими, как и остальные подписи сниппета. Подписи самого блока — ключи
`run_*` в `i18n/`, см. [i18n.md](i18n.md).

`output-mode`, отличный от текста (`table`, `svg`, `iframe`…), строит свой DOM —
такие результаты остаются в родном блоке codapi, а записанный вывод не трогается.

#### Редактор {#run-editor}

Тема одевает собственный интерфейс codapi (Run, статус) в палитру и
**заменяет его редактор**. При `editor="basic"` или `editor="external"` у блока
появляется кнопка **Edit**, а по ней — полноценный режим правки:

- подсветка живёт во время набора: клиентский Go-лексер выдаёт те же классы
  Chroma, что и сборка (родной редактор codapi срезает подсветку при первом
  фокусе — именно это и заменяется);
- пока режим открыт, блок поднят на тон над полотном страницы и остаётся таким
  при потере фокуса, так что правка не теряется от клика мимо;
- **Close** выходит из режима, <kbd>Esc</kbd> делает то же, **Reset**
  появляется, когда код отличается от исходного, и возвращает его точь-в-точь,
  вместе с подсветкой;
- <kbd>Tab</kbd> / <kbd>Shift+Tab</kbd> — отступ, а при выделении нескольких
  строк — сдвиг блока; <kbd>Enter</kbd> держит отступ и раскрывает тело между
  парой `{` `}`; скобки и кавычки закрываются сами, оборачивают выделение и
  пропускают собственную закрывающую; <kbd>⌘/Ctrl+/</kbd> — комментарий;
  <kbd>⌘/Ctrl+Enter</kbd> — запуск; отмена и повтор — браузерные.

`editor="off"` оставляет листинг только для чтения с кнопкой Run. Полная
переверстка блока теряет подсветку `hl_lines` до конца сессии — Reset возвращает
её. Подписи — ключи `js_code_*` в `i18n/`.

## Ссылки {#links}

Внутренние ссылки пиши **контент-путями**, а не выходными URL: hook рендера
ссылок разрешает их через `site.GetPage` и переписывает в канонический пермалинк
— ссылка переживает смену слага, а на многоязычном сайте ещё и разрешается в
перевод на языке текущей страницы.

```md
[гайд про бандл](/inside/anatomy/guide-is-a-bundle)              ← контент-путь, разрешается
[его раздел](/inside/anatomy/guide-is-a-bundle#two-touches)      ← фрагмент сохраняется
```

Битая внутренняя ссылка **валит сборку** (`params.linkcheck = "error"`, по
умолчанию) или ругается в лог (`"warn"`).

Корневой путь с расширением — `/index.xml`, sitemap, статичная выгрузка — не
контент-страница, поэтому проверку по страницам он пропускает и уходит через
`relURL`. Именно это оставляет его живым на сайте, который лежит в подпути
(`https://example.github.io/taiga/`), где буквальный `/index.xml` указал бы в
корень домена и отдал 404.

## Картинки {#images}

Картинка в тексте — обычная markdown-картинка, и файл ищется по имени: точный
путь рядом со статьёй, потом просто имя файла где угодно в её бандле, потом в
`assets/img/`. Поэтому обычно хватает самой короткой формы:

```md
![Бланк сертификата: кому выдан, публичный ключ, кто поручился](cert-fields.png)
```

Если у картинки есть markdown-заголовок, под ней появляется подпись,
отцентрованная вместе с картинкой:

```md
![alt](cert-fields.png "Что лежит в сертификате")
```

Имя, которое ни во что не разрешилось, даёт предупреждение, а
`hugo --panicOnWarning` превращает его в упавшую сборку: опечатка не уедет в
прод битым `<img>`.

### Обтекание: картинка сбоку от текста {#img-right}

Вспомогательную картинку — ту, что иллюстрирует абзац, а не прерывает его, —
можно пустить по правому полю, чтобы текст шёл рядом. Пометь абзац самой
картинки классом `{.img-right}`:

```md
![Бланк сертификата, заполненный гофером](cert-fields.png)
{.img-right}

**x509.** Сертификат — это строгий формат: кому выдан, публичный ключ, кто за
него поручился…
```

Работать это будет при трёх условиях, и два из них ломаются молча:

- **Строка с атрибутом обязана примыкать к строке картинки.** Это markdown-атрибут
  (`markup.goldmark.parser.attribute.block` — сайт включает его в своём
  `hugo.toml`, тема этого сделать не может), и Hugo вешает его на блок прямо
  над строкой. Пустая строка между ними — и строка выбрасывается без единого
  слова: ни класса, ни ошибки, ни самого `{.img-right}` в выводе.
- **Обтекать должна проза.** Блоки кода, таблицы и коллауты сбрасывают обтекание
  нарочно: коробка, делящая строку с картинкой, читается как сломанная вёрстка,
  а не как макет. Поэтому после картинки нужен текст — и его должно хватить,
  чтобы заполнить колонку.
- **Уже 620px колонка не делится**, и картинка возвращается на всю ширину. Это
  не чинится — просто не считай обтекание, когда смотришь, как раздел читается
  с телефона.

Картинка занимает 44% колонки и сохраняет подпись, если та есть.

## Диаграммы (вместо картинок) {#diagrams}

Картинок в гайдах у темы нет — диаграммы памяти собираются руками из HTML внутри
блока `raw`. Строительные детали (всё стилизует тема):

```md
{{</* raw */>}}
<div class="mem">
  <div class="mem-lab">заголовок слайса <span class="tot">→ 24 B</span></div>
  <div class="header">
    <div class="header-word ptr" data-tip="ptr · указатель"><span class="wk">ptr</span><span class="wv">→</span></div>
    <div class="header-word" data-tip="len · длина"><span class="wk">len</span><span class="wv">3</span></div>
  </div>
  <div class="mem-row"><div class="word live" data-tip="элемент">e0</div><div class="word spare" data-tip="запас">··</div></div>
</div>
{{</* /raw */>}}
```

- Ячейки `.mem`: `.word.live` / `.spare` / `.ro` / `.ptrcell` / `.dead`; ячейки
  заголовка — `.header-word.ptr` / `.tab`. Любой `data-tip` бесплатно получает
  тултип.
- Байтовая полоса: `.byte-strip > .byte-seg > .cells > .byte-box.{f0|f1|f2|pad}`
  плюс подпись `.seg-tag` (`.seg-tag.padtag` — для паддинга).
- Живой пример и того, и другого — страница `reference/kitchen-sink` в демо.
- У спана с битовой картой есть свой шорткод, `{{</* spanmap */>}}`, а у чисел —
  [Данные в тексте](#data): бери их — в Obsidian сырой HTML виден как стена
  исходника.

## Данные в тексте {#data}

Числа, которые читатель должен сравнить с одного взгляда — строка обещаний, два
размера рядом, кривая с обрывом, — пишутся **данными в Markdown**, а рисует их
тема. Ни HTML в гайде, ни своего виджета: тот же исходник в любом
Markdown-просмотрщике читается как обычный список или таблица, и Obsidian рисует
его тоже (тема Taiga и плагин taiga-companion).

| Что | Как писать | Чем рисуется |
|---|---|---|
| Строка из 2–4 крупных чисел | `> [!stats]` над списком | только CSS |
| Число с деталью в таблице | `−41% *9,2 → 5,5 нс*` в столбце вправо | только CSS |
| Горизонтальные полосы — серия, группы, части | `{{</* bars */>}}` + таблица | HTML/CSS и крошечная подгонка подписей |
| Линейный график с панелью значений | `{{</* chart */>}}` + таблица или YAML-файл | Observable Plot, по требованию |
| Слоты спана и битовая карта | `{{</* spanmap bits="111100" size="24" */>}}` | HTML/CSS |

Грамматика у всех одна: **жирное** — главное, *курсив в конце* — тихое
дополнение: источник, деталь, пометка. Числа печатаются по правилам языка
страницы (`num_decimal`, `num_group` в i18n) с настоящим минусом.

Собственный `hugo.toml` темы не задаёт настроек разметки; сайту на теме нужен
`markup.goldmark.renderer.unsafe = true` (в демо и на golang.guide он есть): эти
фигуры — HTML, который шорткоды вставляют в поток Markdown.

### stats — строка крупных чисел {#stats}

```md
> [!stats] обещания из release notes
> - **до 30%** дешевле мелкие аллокации *на микробенчмарке*
> - **~1%** в реальном коде *на программах, которые много аллоцируют*
> - **+60 КБ** к размеру бинаря *независимо от нагрузки*
```

- Каждый пункт начинается со значения **жирным**; текст после него — подпись;
  *курсив в конце* — тихая строка под ней (на телефоне прячется: там строка —
  три колонки по ~110px).
- Текст на строке маркера — подпись под всей строкой. Может быть пустым.
- 2–4 пункта, «плотный» список (без пустых строк между пунктами). Обо всём
  остальном хук предупредит — а CI собирает с `--panicOnWarning`.
- На странице это остаётся `<ul>`: скринридер читает «список, 3 пункта», RSS
  показывает список.

### Число с деталью в таблице {#table-details}

```md
| 24 байта | M4 Pro | Genoa |
|---|---:|---:|
| Без указателей | −41% *9,2 → 5,5 нс* | −28% *27,0 → 19,5 нс* |
```

В столбце, **выровненном вправо**, курсив в конце ячейки после текста становится
тихой второй строкой под числом — абсолютные значения за процентом. Ячейка, где
курсив — всё содержимое, остаётся курсивом; остальные столбцы не трогаются.
Заменяет `−41%<br><small>…</small>`.

### bars {#bars}

```md
{{</* bars mark="2" note-color="green" */>}}
| | Прирост бинаря |
|---|--:|
| **Go 1.26** *под флагом, до 512 Б* | +155 КБ |
| **Go 1.27** *в релизе, до 80 Б* | +44 КБ *в 3,5 раза легче* |
{{</* /bars */>}}
```

- **Первый столбец** — подпись строки: `**имя** *подпись*` встают друг под
  другом, простой текст — просто имя.
- **Ячейка значения** печатается как написана, а длину полосы даёт её **первое
  число** (запятая — десятичный знак, разряды — через пробел, `−` и `-` оба
  минус, рисуется модуль). Курсив в конце — пометка после полосы. `~` или пустая
  ячейка показывают свой текст без полосы.
- **Форма следует из таблицы.** Один столбец значений — полоса на строку.
  Несколько — группа на строку, по полосе на столбец в цвете столбца, имя
  полосы — из шапки. `stack="true"` — столбцы становятся частями одной полосы,
  различаются заливкой (сплошная, штриховка, заливка слабее — поэтому частей не
  больше трёх, четвёртая даёт предупреждение), сумма — на конце, части
  расписаны строкой под полосой, легенда — из шапки: `**коротко** *длиннее*`
  даёт части имя и строку легенды.
- **Строка, где все ячейки значений пусты,** — заголовок группы: `**Genoa**
  *выигрыш −28% → −35%*` ставит имя слева, курсив — справа.
- **`whole="100"` — каждая полоса целая,** а значение — её часть, отмеченная
  на конце полосы: тот же цвет, только бледнее, подпись внутри этой части (или
  на сплошной перед ней, если часть слишком узкая). Для экономии или доли по
  машинам: `−41%` — сколько изменение убрало из полной полосы старого времени.
  Больше ничего не рисуется — ни суммы, ни легенды; что такое полоса, скажи в
  подписи.

| Параметр | Смысл |
|---|---|
| `colors` | По столбцам (в стеке — по группам): `ink` `ghost` `blue` `green` `red` `gold` `violet` `copper` `accent`. По умолчанию: `ink` для одной серии, иначе порядок палитры. |
| `max` | Правый край шкалы. По умолчанию — самая длинная полоса. |
| `mark` | Строки, залитые полностью, с 1 как в таблице (`mark="2"`, `mark="1 3"`); остальные становятся «призраками». |
| `stack` | `"true"` — см. выше. Всегда со значением: Hugo не смешивает голый флаг с именованными параметрами. |
| `unit` | После суммы стека, как написан (`unit=" нс"`). |
| `digits` | Стек печатает части и сумму с таким числом знаков. Пиши части точно (`32,25` + `20,68`) — и сумма выйдет 52,9, а не 53,0, как сложились бы округлённые. |
| `note-color` | Цвет пометок после полос. По умолчанию — вторичный текст. |
| `whole` | Сколько стоит целая полоса (`whole="100"` для процентов) — см. выше. Не смешивается ни со `stack`, ни с `max`. |
| `cap`, `note` | Подпись ставит полосы в рамку виджета — как подписан виджет. Без неё они стоят в тексте. |

Подпись стоит внутри конца полосы, чернилом, подобранным под цвет и палитру по
контрасту; слишком короткая полоса выносит её наружу. Это прикидывается при
сборке и перемеривается на странице (`modules/barsfit.js`). Длина полосы берётся
из напечатанного текста, так что `−41%` рисует 41, а не стоящие за ним 40,58 —
на такой шкале разницы не видно.

### chart {#chart}

Линейный график: точки, соединённые по сериям; прицел, прилипающий к ближайшему
измеренному x; панель значений как у Grafana (числа и детали по сериям, идёт за
курсором и не закрывает читаемую точку); строка значений над графиком на
тач-экране; стрелки на клавиатуре. Две формы:

````md
{{</* chart x="размер объекта, Б" y="нс на операцию" x-unit=" Б" y-unit=" нс" colors="blue green red" cap="Выброс на 128 байтах" */>}}
| Размер | M4 Pro | Genoa | Skylake |
|--:|--:|--:|--:|
| 80 | 12,65 | 34,99 | 68,07 |
| 96 | *13,18* | 34,61 | 70,30 |
| 128 | 55,48 | 41,40 | 78,31 |
{{</* /chart */>}}

{{</* chart src="charts/alloc-cliff.yaml" cap="Где кончается ускорение" note="— go1.27, выкл → вкл" /*/>}}
````

**Инлайн-форма** — простой случай: один набор данных, настройки — параметрами.
Первый столбец — x (его первое число), каждый следующий — серия с именем из
шапки. **Файловая форма** берёт всё из YAML-файла в бандле страницы и обязана
**самозакрываться** (`/>`): график читает своё тело, и незакрытый тег проглотил
бы текст после себя.

**Грамматика ячейки** — одна и та же в таблице, в YAML и в Obsidian:

| Ячейка | Смысл |
|---|---|
| `12,65` | значение |
| `*13,18*` | полая точка из другого источника — не соединяется и рвёт линию |
| `~` | разницы не видно: полая точка на нуле, пунктир к соседям |
| пусто, `null`, `—` | нет данных: линия рвётся |
| `12,65 *деталь*` | любое из выше плюс деталь для панели и таблицы без JS |

Параметры инлайн-формы: `x`, `y` (заголовки), `x-unit`, `y-unit` (после
значений; единица без пробела впереди — `%` — идёт и в подписи шкалы),
`x-digits`, `y-digits`, `x-domain`, `y-domain` (`"0 136"`; обратный домен вроде
`"0 -50"` рисует величины вверх), `x-ticks`, `y-ticks`, `x-narrow` (деления x уже
480px), `colors`, `shapes` (`circle square triangle diamond star cross`),
`rule` + `rule-label`, `zone` (`"80 136"`) + `zone-label`, `legend`, `same`,
`hollow` (строки легенды для `~` и полых точек), `rest` (x, который строка
значений показывает в покое), `summary` (фраза для скринридера), `height`
(`"250 290"`: узкий и широкий), `cap`, `note`. Неизвестный параметр —
предупреждение.

**Файловая форма**, `charts/alloc-cliff.yaml` рядом с `index.md`:

```yaml
x: {title: "размер объекта, Б", unit: " Б", domain: [0, 136], ticks: [8, 24, 80, 128], narrow: [8, 80, 128]}
y: {title: "насколько дешевле одна аллокация", unit: "%", digits: 0, domain: [0, -50]}
series:
  - {name: M4 Pro, color: blue, shape: circle, note: "×4,4"}   # note: жирным после имени в легенде
  - {name: Genoa, color: green, shape: square}
rules: [{x: 80, label: "80 Б"}]
zones: [{from: 80, to: 136, label: "общий путь"}]
jumps: [{series: M4 Pro, from: 80, to: 128, label: "×4,4"}]    # стрелка от одного x к другому
legend: {title: "80 → 128 Б:", same: "~ — разницы не видно", hollow: "другой прогон"}
rest: 80
summary: "До 80 байт включительно дешевеет на всех машинах, с 88 байт — ни на одной."
modes:                                    # переключатель — или `rows:` для одного набора
  - label: без указателей
    rows:
      - [80, "-20.47 *12,5 → 10,0 нс*", -25.53]
      - [88, "~", "~"]
  - label: с указателем
    rows:
      - [80, -29.74, -26.03]
      - [88, "~", -5.62]
```

- Ключи — строчные. `rows` и `modes` вместе нельзя (ошибка сборки).
- **`"~"` — в кавычках**: голая `~` в YAML — это null, и точки не будет вовсе.
  Всё, что YAML может прочесть иначе (`yes`, `no`, `0x10`), — тоже в кавычки.
- Строка — `[x, по ячейке на серию]`; короткая или длинная строка — предупреждение.
- **Два языка:** Hugo отдаёт `alloc-cliff.ru.yaml` русской странице под именем
  `alloc-cliff.yaml`, так что у двуязычного гайда один `src`.
- Файл читается при сборке и не публикуется.

**Что уезжает на страницу.** В фигуре — таблица каждого режима (вид без JS: его
получают RSS, читатель без JavaScript, страница, где Plot не загрузился, и
скринридер, когда график уже нарисован) и данные в JSON. Рантайм
(`assets/js/charts/`) и Observable Plot грузятся только на страницах с графиком, а
Plot — только когда фигура подходит к экрану; цвета — роли палитры, так что
смена палитры перекрашивает график без единой строки JavaScript.

**Рантайм общий.** Плагин Obsidian рисует графики побайтной копией
`assets/js/charts/{core,fmt}.js` и той же сборкой Plot; его drift-проверка
падает, как только они разойдутся. Тест-векторы грамматики
(`assets/js/charts/cases.json`) прогоняются и через рантайм, и через Hugo-партиалы,
которые печатают таблицы без JS: `node scripts/check-charts.mjs`.

### spanmap {#spanmap}

```md
{{</* spanmap bits="111100" size="24" */>}}
```

Спан из одинаковых слотов и его битовая карта, по биту на слот. Выбранный слот —
первый ноль (то самое правило выделения, которому учит фигура), а мерка над
полосой и адрес в выводе — его номер, умноженный на размер слота. От 2 до 12
битов; `unit` меняет знак байта; слова — из i18n (`spanmap_*`). Полная карта так
и говорит, вместо выбора слота.

Работает внутри карточки `{{</* term */>}}` — на отдельной строке с пустыми
строками вокруг (тело карточки — Markdown, и фигура должна дойти до него одним
HTML-блоком).

### Числа и Plot в своих виджетах {#data-helpers}

Виджету, которому нужно то же, что фигурам, тема даёт это сама — без своей копии:

- `Taiga.fmt(v, digits)` — число так, как его печатают фигуры: десятичный знак
  языка страницы, настоящий минус, округление половины вверх по печатаемой
  цифре, никакого `−0`. `Taiga.num("−41%")` достаёт из строки первое число.
- `Taiga.plot()` — промис с пространством имён Plot, один запрос на страницу;
  `Taiga.plotWhenNear(root, live)` вызывает `live(Plot)`, когда `root` подходит к
  экрану. Обоим нужен `plot: true` во front matter (график включает его сам). В
  сборке есть марки `plot dot link arrow text rect ruleX ruleY gridY`;
  `scripts/vendor-plot/` пересобирает её с другими.

В Obsidian виджеты работают в песочнице-фрейме: `Taiga.fmt` там есть,
`Taiga.plot()` отказывает, и виджет остаётся со своим `figure.html`.

### Что выбрать — памятка для авторов и агентов {#data-checklist}

- **Два–четыре главных числа**, с которыми раздел дальше спорит → `[!stats]`.
- **Процент с абсолютными значениями** в таблице → ячейка с деталью, а не
  `<br><small>`.
- **Несколько величин рядом** (размеры, цены, времена) → `bars`; несколько машин
  или форм → группы; сумма и её доля → стек; экономия или доля по машинам →
  `whole="100"`.
- **Как величина меняется по x** (размер, версия, нагрузка) → `chart`; один набор
  данных → инлайн-таблица, что-то богаче → YAML-файл.
- **Спан, битовая карта, слот** → `spanmap`.
- **Всё остальное** — взаимодействие, которое объясняет механизм, → [виджет](#widgets).
  Никакого сырого HTML в Markdown для фигуры, которую покрывает список выше.
- Проверка: сборка сайта с `--panicOnWarning` (шорткоды предупреждают о каждой
  кривой ячейке и параметре), потом страница в браузере — со светлой палитрой и
  на 360px.

## Виджеты {#widgets}

Живая иллюстрация — это два касания, без правки шаблонов и `<head>`:

1. В тексте: шорткод `widget` (выше).
2. Рядом с `index.md`: папка `widgets/<id>/` — `widget.js` и, если готовых
   классов ниже не хватает, `widget.css`. Тема сама находит все
   `widgets/**.js` и `widgets/**.css` в бандле, склеивает их в порядке имён
   файлов, собирает и проставляет отпечаток и подключает результат **только
   на этой странице**.

Каждую фигуру регистрируй по id её mount'а, в `widgets/w-escape/widget.js`:

```js
Taiga.widget("w-escape", function (root) {
  // `root` — это mount .w-root; собирай интерактив здесь (ванильный JS).
});
```

`Taiga.widget` — крошечный рантайм внутри темы, и этот вызов — единственное,
что не поменяло форму: он всё так же ждёт DOM, находит mount по id и отдаёт
его твоему колбэку внутри `try/catch` — упавший виджет пишет в консоль и не
роняет соседей, а отсутствующий mount (шорткод убрали из текста) молча
пропускается. Id в шорткоде и в `Taiga.widget(…)` должны совпадать символ в
символ.

Бандл с более чем одним виджетом может завести папку `widgets/_shared/` для
кода или классов, нужных нескольким сразу, — `lib.js` (рантайм-guard плюс
общие хелперы) и `shared.css`. Сборка сортирует по имени файла, и `_shared`
всегда идёт раньше любой папки `w-*`, так что `_shared/lib.js` попадает в
склеенный скрипт первым, и его объявления уже видны каждому
`widgets/<id>/widget.js` после него — это фрагменты одной сборки, а не
отдельные файлы каждый со своим замыканием. Разобранный, с комментариями,
пример всей раскладки — статичный виджет, интерактивный и `_shared/` — лежит
на странице демо `reference/widget-anatomy`.

Пользуйся готовыми классами темы — тогда виджет выглядит родным без единой строки
своего CSS: `.w-row` (ряд контролов), `.w-btn` (`.primary`/`.ghost`), `.w-num`
(большое число; добавь `.tick` на его `<b>`, чтобы анимировать смену),
`.w-badge.ok`/`.alloc`, `.w-cap` (строка вывода), слайдеры — `.gc-slider-row` с
отсчётом `.nval`. Виджет должен работать офлайн, без зависимостей, и иметь
честное начальное состояние. Числа печатай через `Taiga.fmt`, а виджет, который
рисует Observable Plot, берёт его через `Taiga.plot` — см.
[Данные в тексте → помощники](#data-helpers); фигура, которая должна читаться
как часть текста, снимает рамку через `bare="true"`.

### Одна папка widgets/ на два языка {#widgets-i18n}

**Папка `widgets/` бандла общая для всех переводов.** У Hugo нет языковой
версии ресурса страницы: `index.md` и `index.ru.md` — две страницы *одного*
бандла, а папка `widgets/` у бандла ровно одна. Поэтому виджет с зашитыми
строками на половине двуязычного сайта покажет не тот язык — и ничто об этом
не предупредит.

В демо это решено ветвлением по языку документа, который тема ставит в
`<html lang>`:

```js
Taiga.widget("w-series-math", function (root) {
  var RU = document.documentElement.lang.indexOf("ru") === 0;
  var L = RU
    ? { onPart: "ты на части", cap: function (n, total) { … } }
    : { onPart: "you are on part", cap: function (n, total) { … } };

  // …собираем виджет, беря каждую видимую строку из L
});
```

Держи строки в одном объекте на язык в начале виджета и ниже не вставляй ни
одного литерала — вся дисциплина в этом. `indexOf("ru") === 0`, а не `=== "ru"`,
чтобы `languageCode` вида `ru-RU` тоже совпал. Полный образец —
`exampleSite/content/inside/anatomy/series-knows-itself/widgets/w-series-math/widget.js`.

То же верно для любого другого ресурса бандла: подменная `og.png`,
`figure.html` и всё, что лежит под `widgets/`, — по одной копии на оба языка.

## Обложки (OG-картинки) {#covers-og-images}

У каждого гайда есть Open Graph-обложка, которую тема рисует на сборке — подложка
плюс кикер серии, заголовок и минуты — **без единого действия автора** и на языке
страницы. Перебить для одного гайда: положить в его бандл `og.png` (или `og.jpg`)
либо задать `og_image:` во front matter. Сменить стиль для страницы — `og_style:`;
для всего сайта — `params.ogImages.style`
(см. [customizing.md](customizing.md#og-cover-styles)).

Гайд может назвать и собственную картинку. Поле одно, и оно кормит сразу
баннер в ленте и карточку шаринга — разойтись они не могут:

```yaml
cover: cover.webp
```

Приоритет, от старшего к младшему: `cover` → `og.png` в бандле → `og_image:` →
нарисованная обложка. То есть названная картинка выключает генератор для этой
страницы.

Путь разрешается так же, как у картинки в Markdown: рядом со статьёй (точный
путь либо просто имя файла где угодно в её бандле), затем в `assets/` и
`assets/img/`. Ведущий `/` отбрасывается перед этими поисками, так что
`/img/cover.webp` всё равно найдёт `assets/img/cover.webp`. Всё, что не нашлось,
уходит как URL — так работают файл в `static/` и картинка на чужом хосте, — а
голое имя, не совпавшее ни с чем, пишет предупреждение: это может быть только
опечатка.

`cover` кормит карточку шаринга, карточку Twitter и JSON-LD. Та же картинка
появляется и на страницах самого сайта, если он это включил:
`params.home.feedCover = "banner"` даёт карточке ленты полосу-обложку, а
`params.article.cover` печатает картинку над текстом статьи. Делает это только
`cover` — картинка внутри текста гайда остаётся там, куда её поставил автор, а
нарисованная OG-обложка дальше мета-тегов не идёт: запечённый в ней заголовок
дублировал бы тот, что напечатан рядом.

Полоса **кропает** картинку до `--feed-cover-ratio` (по умолчанию `3 / 1`),
статья показывает её **целиком**. Нарисуй обложку в пропорции полосы — и в обоих
местах будет один и тот же кадр; у более высокой в ленте срежет верх и низ. Если
графике нужна другая форма, сайт перенастраивает эту одну переменную в
`custom.css`.

Растровую обложку тема пережимает в WebP до двойной ширины колонки и никогда не
растягивает; SVG, файл в `static/` и картинка на чужом хосте проходят
нетронутыми.



## Рубрики {#rubrics}

Рубрика — это секция с `_index.md`:

```yaml
title: "Приёмы"
params:
  label: "руководство"      # подпись кикера у гайдов этой рубрики и ссылка на карточке ленты
  slug_mono: "howto"        # моно-слаг в кикере самой страницы рубрики
  sub: "от установки до первого гайда."   # необязательный подзаголовок h1
  lead: "О чём эта рубрика."
  card_line: "Бери и поехали."            # необязательная строка на карточке рубрики на главной
  foot: "Заключительная заметка под рубрикой."
```

Перечисли секцию в `params.rubricSections` (конфиг сайта) — тогда её листовые
страницы получат полный макет гайда.

## Перевод гайда {#translating-a-guide}

Языковые версии связываются **суффиксом файла**, внутри одного бандла:

```
content/inside/anatomy/series-knows-itself/
  index.md        ← язык по умолчанию
  index.ru.md     ← перевод
  widgets/        ← общая для обоих (см. выше)
```

Индексные страницы рубрик и серий связываются так же: `_index.md` ↔ `_index.ru.md`.

Два поля обязаны быть **одинаковыми в обоих файлах**:

- **`slug`** — чтобы страница и её перевод делили путь URL
  (`/inside/anatomy/series-knows-itself/` и `/ru/inside/anatomy/series-knows-itself/`).
  Переключатель языка тогда прыгает между ними на месте, а не выбрасывает читателя
  на главную.
- **`tags`** — чтобы чипы, облако тегов и лента `/tags/#<tag>` сходились с обеих
  сторон. Переведёшь тег — получишь два полупустых облака.

Всё остальное — `title`, `description`, `lead`, `rail_title`, текст — переводится.
`weight`, `mins` и `version` структурные: копируй как есть.

Контент-пути во front matter (`related:`) и в ссылках разрешаются **по языку
страницы**, поэтому пишутся одинаково в обоих файлах: `related:
["inside/anatomy/palette-is-a-file"]` из `index.md` возьмёт английскую страницу, а из
`index.ru.md` — русскую.

Со стороны темы больше ничего не нужно: переключатель языка появляется сам,
альтернативы `hreflang` проставляются, а дата в ленте собирается из i18n-названий
месяцев — отдельный партиал на язык зеркалить не надо.

## Голос {#voice}

Эталон — сами гайды демо (`exampleSite/content/`). Коротко:

- Разговорно, точно, на «ты». Без корпоративного тона и рекламы.
- Дуга — **наивно → больно → починили → а вот как оно на самом деле**: сперва
  простая модель, потом место, где она ломается, потом настоящий механизм.
- Одна сквозная линия на гайд; возвращайся к ней.
- Чекпоинт после большого блока: `> [!recap]` — *«Теперь ты можешь …»*.
- Короткие бытовые метафоры (библиотечный формуляр, бирка на посылке).
- Виджеты вплетены конкретной задачей: «Поиграй — …».
- Заголовки `h2` — короткие и по делу, а не «Введение» и «Заключение».
- В конце — «Что дальше» и мост к следующей части.

При переносе текст копируется дословно — не правь молча; нашёл настоящую ошибку —
почини и скажи об этом.
