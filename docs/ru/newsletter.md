# Подписка на рассылку

**По умолчанию выключена — и щёлкнуть рубильником это меньшая часть работы.**
Тема рисует форму и больше ничего: не хранит адреса, не отправляет письма, не
знает никаких кредов. Снаружи неё должны появиться три вещи.

1. **Движок рассылки** — то, что владеет списком, шлёт письмо подтверждения
   (double opt-in) и разбирается с отписками: [listmonk](https://listmonk.app),
   Buttondown, Mailchimp, собственный скрипт поверх почтового API. Если хостишь
   сам — плюс домен, которому разрешено слать почту: SPF, DKIM, DMARC и
   репутация, которую надо беречь.
2. **Свой эндпоинт**, куда шлёт форма, — несколько строк на Cloudflare Worker,
   serverless-функция, ручка в бэкенде. Он нужен потому, что статический сайт не
   умеет хранить секреты, а ключ от движка — секрет.
3. **Антибот** перед этим эндпоинтом —
   [Turnstile](https://developers.cloudflare.com/turnstile/), rate limit или и
   то и другое. Открытую ручку подписки находят и начинают долбить за считанные
   дни, а счёт за отправленные письма — твой.

Это инфраструктура со счётом и почтовым ящиком, а не настройка темы. Пока её
нет, рубильник лучше не трогать: при `newsletter.enable = false` тема не
добавляет **ничего** — ни разметки, ни правила `nl-` в CSS-бандле, ни модуля в
JS-бандле, ни конфиг-скрипта, ни лишних i18n-ключей. Минимальный конфиг, при
котором хоть что-то появится, — три строки:

```toml
[params.newsletter]
  enable = true
  endpoint = "/api/subscribe"   # твой прокси — см. «Два режима» ниже
```

Что за это дают: кнопка-колокольчик в шапке с поповером, блоки, которые автор
ставит внутрь гайда, CTA под списком глав серии, ссылка в футере и «голая»
форма для страницы, написанной прозой. Одна форма, одна машина состояний, один
набор текстов — и каждое из пяти мест включается отдельно.

**Сама страница подписки — твоя**, не темина: это обычная страница контента
(`content/subscribe.md` в демо), на которую указывают поповер в шапке и ссылка
в футере. Выключенная фича убирает с неё формы, но не снимает её с публикации —
это `build.render = "never"` в её front matter или удалённый файл.

## Как включить

```toml
[params.newsletter]
  enable = true
  mode = "worker"                    # "worker" | "direct"
  endpoint = "/api/subscribe"        # куда шлёт форма
  turnstileSiteKey = ""              # публичный site key; пусто = без капчи
  contactEmail = ""                  # кому предложить написать, если не вышло
  subscribePage = "/subscribe/"      # куда ведут поповер и футер
  [params.newsletter.placements]
    header = true                    # колокольчик рядом с иконкой фида
    footer = true                    # ссылка в строке футера
    articleEnd = false               # авто-блок после мостика серии
    seriesLanding = false            # CTA под списком глав серии
```

| Ключ | Тип | По умолчанию | Что делает |
|---|---|---|---|
| `newsletter.enable` | bool | `false` | Главный рубильник. `false` ⇒ не рендерится ничего, что бы ни стояло во флагах ниже. |
| `newsletter.mode` | `"worker"` \| `"direct"` | `"worker"` | Как браузер добирается до списка. Любое другое значение валит сборку. |
| `newsletter.endpoint` | string | `"/api/subscribe"` | Куда шлёт форма. Выводится **как есть** — без `baseURL`: в режиме worker это маршрут на твоём домене, в direct — абсолютный URL. |
| `newsletter.listUUID` | string | `""` | Только для direct и там **обязателен**: UUID листа. Без него сборка падает, а не выпускает форму, которая молча теряет адреса. |
| `newsletter.turnstileSiteKey` | string | `""` | Публичный site key [Turnstile](https://developers.cloudflare.com/turnstile/). Пусто ⇒ в браузере нет проверки. Секретная половина живёт на эндпоинте, но не здесь. |
| `newsletter.contactEmail` | string | `fromAddress` | Адрес, на который состояние ошибки предлагает написать, ссылкой `mailto:`. По умолчанию берётся `newsletter.fromAddress`; пусто в обоих ⇒ строка не рендерится: предложить написать в никуда хуже, чем не предлагать вовсе. |
| `newsletter.subscribePage` | string | `"/subscribe/"` | Страница, на которую ведут ссылка в поповере и ссылка в футере. Проходит через `relLangURL`, поэтому переживает подпуть и язык. |
| `newsletter.placements.header` | bool | `true` | Колокольчик с поповером, четвёртый в правом блоке шапки. |
| `newsletter.placements.footer` | bool | `true` | Ссылка в футере, между ссылками сайта и фидом. |
| `newsletter.placements.articleEnd` | bool | `false` | Авто-блок в конце каждого гайда, под мостиком серии. Пропускается на странице, где автор написал свой `{{</* newsletter-cta */>}}`. |
| `newsletter.placements.seriesLanding` | bool | `false` | CTA под списком глав на лендинге каждой серии. |

Два «хромовых» размещения включены по умолчанию: включить рассылку и не найти,
где подписаться, — вот что было бы неожиданно. Два «контентных» выключены:
поставить форму в каждый гайд — это решение про чужой текст, поэтому его
принимают явно. У срединного блока флага нет вовсе — это шорткод, который автор
ставит руками, в конкретном гайде.

## Два режима

**`worker`** — форма шлёт JSON в прокси на своём же домене:

```jsonc
{ "email": "reader@example.com", "list": "main", "website": "", "ts_token": "…" }
```

`website` — honeypot (у человека всегда пустой), `ts_token` — токен Turnstile,
если он есть. Прокси отвечает **202** («принято, письмо-подтверждение ушло»),
**400** на кривой адрес и чем угодно ещё на неудачу. Секреты живут там: секрет
Turnstile, креды списка, rate limit. Страница не знает имени провайдера.

**`direct`** — форма шлёт напрямую в публичный эндпоинт подписки
[listmonk](https://listmonk.app):

```jsonc
{ "email": "reader@example.com", "name": "", "list_uuids": ["<listUUID>"] }
```

Это путь деградации: локальная разработка или упавший прокси. Своей
антибот-защиты перед ним нет, так что как постоянная конфигурация он не годится.

В любом режиме читателю говорят одно из трёх — принято, «похоже на опечатку»,
«не получилось». Форма никогда не сообщает, что адрес уже в списке: при double
opt-in это работа письма, а на странице такой ответ выдал бы подписчиков любому,
кто спросит.

## Turnstile и почему он может не сработать

Виджет **невидимый** и запускается на сабмите. Скрипт подключается только там,
где применим (режим worker, задан site key, на странице есть форма), и его
никогда не ждут: если токен не пришёл за **2 секунды**, запрос уходит без него,
а решение принимает эндпоинт. Читателей с блокировщиками на техническом сайте
много, и никто из них не должен остаться без возможности подписаться.

Honeypot работает всегда: настоящее поле `website`, спрятанное классом, а не
инлайн-стилем (часть ботов игнорирует всё, что скрыто инлайном), вне таб-порядка
и вне дерева доступности.

## Шорткоды

Пять. **На сайте с выключенной фичей они валят сборку** — по одной ошибке на
вхождение, с именем шорткода и страницей:

```
ERROR newsletter: {{</* newsletter */>}} on page "/guides/scheduler" rendered nothing,
because params.newsletter.enable is false. …
```

Альтернатива — молча отрендерить пустоту — это ровно тот способ, которым тема
зарабатывает вопрос «я вставил шорткод, ничего не появилось, почему?». Со
страницы на него не ответить: разметка правильная, шорткод существует, а
причина — булев флаг в конфиге, которого у автора может и не быть.

Но рубильник обязан оставаться рубильником. Выключение `enable` на живом сайте
— эндпоинт лёг, движок меняется, пришёл юрист — не должно начинаться с правки
всех гайдов, где стоит блок. Поэтому ошибка **гасится по id**:

```toml
ignoreLogs = ['newsletter-disabled']
```

С этой строкой шорткоды снова рендерят пустоту, тихо, и гайд переживает и
запуск, и откат, не меняя ни строчки. Это осознанная половина осознанного
действия — одна строка в том же файле, где выключен рубильник.

### newsletter — срединный блок

```md
{{</* newsletter label="серия · продолжение" dismiss="sched-1" */>}}
Это первая статья серии. Оставьте почту — пришлю продолжение.
{{</* /newsletter */>}}
```

Тихий блок, отбитый одними отступами: моно-надзаголовок, предложение голосом
самой статьи, форма. С `dismiss=` появляется крестик.

Крестик — глиф 12px в зоне 34×34 (контрольный квадрат темы), стоящий на
оптической линии первой строки блока, а не в его углу: у блока нет рамки, и
первая строка — единственный край, с которым глаз может его связать. Первая
строка отдаёт под него 40px, чтобы текст физически не мог заехать под кнопку
(`max-width` у надзаголовка, если он есть, и флоат в `.nl-txt::before`, если
нет); всё, что ниже, идёт на полную меру. В покое крестик держит `opacity:.4`
и выходит на полную по ховеру или фокусу с клавиатуры — заметен настолько,
чтобы его нашли, в том числе на тач-экране, где ховера нет и он в покое ещё
чуть плотнее. В разметке он **последний**: с клавиатуры сначала поле и кнопка
подписки, и только потом «убрать».

Сворачивание блок не удаляет — он схлопывается в одну приглушённую строку
(«Форма подписки свёрнута — вернуть») на том же месте, и ссылка разворачивает
его обратно. **Оба состояния переживают перезагрузку** и хранятся **по блоку**
(`localStorage`, ключ `nl.dismiss.<key>`): один и тот же блок может стоять в
каждой части серии, остаётся свёрнутым, если его свернули, и развёрнутым, если
его вернули. Значение в хранилище не менялось с версии, которая блок удаляла,
поэтому тот, кто закрыл блок при старом поведении, увидит строку-призрак, а не
пустоту.

| Параметр | Значение |
|---|---|
| `label=` | моно-надзаголовок над текстом; необязателен |
| `dismiss=` | суффикс ключа localStorage; включает крестик и строку-призрак, в которую блок сворачивается |
| `note=` | строка-обещание под формой. **Опциональный, без дефолта** — не задали, и строки нет вообще. В отличие от остальных размещений, здесь нет фолбэка на i18n: срединный блок говорит голосом статьи, поэтому фраза либо авторская, либо её нет. |

### newsletter-cta — концевой блок

```md
{{</* newsletter-cta title="Дальше — по почте" note="Отписка в один клик." */>}}
Это была первая часть серии. Оставьте почту — пришлю продолжение.
{{</* /newsletter-cta */>}}
```

Та же карточка, что вставляет `placements.articleEnd`; написанная руками, она
лишь заменяет тексты и отменяет автоматическую копию на этой странице. Приоритет
текстов: **параметры шорткода → front matter страницы `newsletterCta` →
дефолты i18n**.

```yaml
newsletterCta:
  title: "Дальше — по почте"
  body: "Серия продолжается…"
  note: "Только анонсы."
```

Положи это в `_index.md` серии — и все её части унаследуют формулировку через
каскад секции; там же этот текст становится текстом CTA на лендинге серии.

### newsletter-inline — голая форма в прозе

```md
{{</* newsletter-inline id="form" note="Придёт письмо с подтверждением." */>}}
```

Без рамки, заливки и заголовка — для страницы подписки и страницы поддержки, где
все остальные предложения тоже написаны обычными предложениями. На `id="form"`
указывает ссылка из поповера (`#form`), и при переходе фокус встаёт в поле.

### newsletter-archive, newsletter-letter-example — опциональные блоки страницы подписки

**Видимость = присутствие.** Написали шорткод — блок есть, удалили — блока нет.
Front matter ни один из них больше не гейтит: это делило одно решение на два
файла, и обычным исходом был шорткод, который месяцами лежит в тексте и ничего
не рендерит, а по markdown не понять, есть на странице блок или нет. Заглушек
«скоро» по-прежнему не бывает — блок, к которому вы не готовы, это строка,
которую вы ещё не написали.

```md
{{</* newsletter-archive url="https://news.example.com/archive/" */>}}

{{</* newsletter-letter-example subject="Очереди: GRQ, LRQ и work stealing" */>}}
…образец письма, markdown…
{{</* /newsletter-letter-example */>}}
```

URL архива едет параметром шорткода, поэтому вся фича — одна строка. Держите её
закомментированной в markdown, пока архив не открыт, и раскомментируйте, когда
откроется.

Пример письма — окно почтовика (полоса окна, Subject, From) вокруг канваса, а на
канвасе лист 600px: форма, которую письмо и правда имеет в клиенте. **Рама и
канвас** — темины, **письмо** — твой markdown. Всё внутри листа остаётся светлым
в любой палитре намеренно: читателю показывают то, что придёт в его ящик, а
тёмный образец врал бы о продукте.

**«Отписаться» в письме и «отписка в один клик» в форме — не рассинхрон.**
`nl_letter_unsub` в футере образца — просто «отписаться»; `nl_note_short` под
формой обещает «отписка в один клик». Формулировки разные намеренно:
в форме это обещание **до** подписки, оно снимает страх «потом не выпутаюсь», а
в письме читатель уже подписан — ему нужна дверь, а не реклама её лёгкости. Не
унифицируйте: боевой шаблон кампании говорит ровно то же самое.

**Типографика листа сгенерирована, а не написана.** Правила под `.nl-letter-body`
в `28-newsletter.css` сняты дословно с `<style>` отправляющего шаблона и
перескоплены, поэтому образец не может разойтись с письмом. Перегенерировать
после правки шаблона кампании:

```sh
cd local/mocks/newsletter/listmonk/tools/render-sample && go run .
```

Скрипт пишет `out/letter-content.css` (вставить поверх сгенерированного блока) и
`out/letter-full.html` — эталонный рендер для сверки со страницей. Блок
нейтрализаторов над сгенерированными правилами гасит собственные prose-стили
сайта, с которыми письму бороться не приходится; держите его только
нейтрализаторами. Сгенерированную половину руками не подкручивайте — именно так
образец начал рисовать ссылки волосяным подчёркиванием вместо сплошного, а
инлайн-код — серым чипом вместо голого моноширинного.

| Параметр | Значение |
|---|---|
| `subject=` | строка Subject (обязателен) |
| `from=` | имя отправителя (по умолчанию `params.author`, затем title сайта) |
| `address=` | адрес From (по умолчанию `params.newsletter.fromAddress`) |

## Тексты

Все строки — i18n (`i18n/*.toml`, префикс `nl_`), блок в конце файлов. Семь
строк, нужных браузеру (сообщения формы), едут в JS через `js-bridge.html` как
`window.THEME_I18N.nlMsg*` — и только на сайте с включённой фичей. В `nl_msg_ok`
есть подстановка `{email}`: туда встаёт введённый адрес, жирным.

У двух результатов есть вторая, тихая строка под статусом. `nl_msg_ok_hint`
отправляет читателя в спам: письмо уходит на каждую попытку, так что невидимое
письмо отфильтровано, а не потеряно. `nl_msg_fail_hint` даёт выход из
единственного тупика, который не лечится повтором (адрес, заблокированный
списком после отбивки, будет отвергнут снова); её `{email}` — это
`newsletter.contactEmail`, он становится обычной ссылкой `mailto:`, а без
адреса строка не рендерится вовсе.

Длинные тексты — страница подписки, аргумент конкретного гайда в его блоке —
это **контент, а не i18n**. Они живут в markdown сайта, где автор правит их, не
трогая шаблоны.

## Доступность

Поповер — disclosure, а не модалка: `aria-expanded` + `aria-controls` на кнопке,
`hidden` на панели, Esc закрывает и возвращает фокус, клик мимо закрывает, при
открытии фокус встаёт в поле. Каждая строка статуса — `role="status"
aria-live="polite"`, поэтому результат озвучивается, не воруя фокус, — а вторая
строка результата пишется в ту же область и тем же присестом, так что
объявление получается одно, а не два; отвергнутый адрес получает `aria-invalid`,
который снимается при первом же вводе. На успехе
форма прячется, а не блокируется — мёртвое поле, по которому всё ещё можно
кликнуть, читается как баг, — и вернуть её можно тихой кнопкой «указать другой
адрес».

На каждом блоке внутри статьи стоит `data-pagefind-ignore`: форма подписки — это
хром, и поиск не должен ею отвечать.

**Модалок и всплывашек по скроллу или таймеру нет.** Все размещения
статические. Это продуктовое решение, а не недоделка.

## Когда читатель уже подписан

Успешная подписка пишет в `localStorage` один булев флаг (`nl.subscribed = '1'`)
— **адрес не сохраняется никогда**. На всех последующих страницах каждое
размещение сворачивается в одну приглушённую строку вместо повторного
предложения: одна и та же форма под каждой статьёй читается как сайт, который не
слушает.

Два места намеренно не трогаются. **Колокольчик в шапке** остаётся на месте: это
навигация, а контрол, который то появляется, то исчезает, хуже контрола, который
всегда там же. **Страница подписки** сохраняет форму: это канонический вход, и на
неё могут прийти, чтобы добавить второй адрес.

Из каждой строки есть путь обратно к форме, потому что флаг может врать — он
знает только, что подписка случилась *в этом браузере*, и не услышит отписку,
сделанную из письма. Поповер несёт этот путь сам («подписать другой адрес»), как
единственное размещение, доступное откуда угодно. Там, где блок иначе был бы
свёрнут, **побеждает «подписан»**: он объясняет, почему формы нет, а предложение
строки-призрака было бы шумом.

Очистка данных сайта сбрасывает состояние. Никакого серверного представления о
«этом читателе» нет — в этом и смысл.

## Менеджеры паролей и расширения масок почты

Bitwarden, 1Password, Firefox Relay и DuckDuckGo находят поле по семантике —
`type="email"` и `autocomplete="email"` — и ставят на него свою кнопку. **Это
правильное поведение, и тема с ним не воюет.** Читатель, который держит по
маске на сайт, — ровно тот читатель, который нужен блогу про приватность, и
ломать ему расширение ради вёрстки — плохой размен.

Поле дружит с ними за счёт двух свойств, и оба легко испортить по неосторожности:

- **Ширина.** Кнопка расширения садится на правый край поля. Широкому полю её
  есть куда принять, тесному — нет. Поэтому форма в поповере шапки
  (`.nl-pop .nl-form`) стоит стеком, а не кладёт поле и кнопку отправки в одну
  строку.
- **Настоящий `label[for]` и уникальный `id`.** Менеджеры связывают поле с его
  лейблом, чтобы понять, что это за форма, а `aria-label` связывать не с чем —
  поэтому у поля есть визуально скрытый `<label>` (`.nl-vh`) и нет
  `aria-label`. На странице форма встречается до шести раз, поэтому `form.html`
  принимает слаг `place` и собирает из него `id="nl-email-<place>"`; два
  шорткода подмешивают свой `.Ordinal`, потому что могут повторяться. Добавляя
  новое размещение, передайте `place`, который на странице больше никто не
  занимает.
- **Никакой анимации геометрии над полем.** Bitwarden меряет поле один раз и
  пересчитывает позицию только на scroll и resize, поэтому панель, которая
  въезжает уже после раскладки, оставляет кнопку по старым координатам.
  Поповер только проявляется (opacity через `@starting-style`) и не двигается.
- **Симметричные горизонтальные паддинги.** Никогда не добавляйте `.nl-field`
  правый `padding`, чтобы «зарезервировать полосу». Оба семейства читают
  computed-паддинг поля и цепляются к его **content**-боксу, поэтому лишний
  правый паддинг толкает их кнопку *влево, в текст*, а Relay вдобавок считает
  по нему ширину ховер-плашки и зоны клика: `2 × padding-right + 25`px. Точные
  формулы и замеры — в комментарии над `.nl-field` в
  `assets/css/28-newsletter.css`.

Если сайту всё же нужно убрать внутриполевую кнопку Bitwarden, добавьте инпуту
`data-bwignore`, переопределив `layouts/_partials/newsletter/form.html`. **Тема
его не ставит.** Атрибут убирает только инлайн-кнопку — заполнение по
горячей клавише и из попапа расширения продолжает работать, — но заодно убирает
привычный большинству способ, так что это осознанный opt-in, а не «починка».
