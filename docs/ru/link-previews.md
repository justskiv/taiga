# Превью ссылок

На точном курсоре ссылка в тексте по наведению растит плавающую **карточку-превью**
— физика терм-карточки, один поповер на страницу. Семь жанров, одна семья:

- **Внутренние** ссылки (на гайд или серию) открывают окно в страницу: шапка
  статьи в миниатюре, зачин плюс целые H2-разделы до бюджета слов, список «дальше
  в статье» и футер «Читать статью». Ссылка с `#якорем` сужает карточку до одного
  раздела; ссылка на лендинг серии показывает оглавление.
- **Telegram**-ссылки на пост из *твоего* канала открывают карточку, собранную из
  t.me на билде — аватар, имя, число подписчиков, текст поста (с фото, цитатами
  реплаев, реакциями и кастомными эмодзи), просмотры и дату.
- **YouTube**-ссылки открывают видео-карточку — превью-кадр (ссылка на ролик),
  длительность, канал, число просмотров.
- **Wikipedia**-ссылки (`*.wikipedia.org/wiki/*`) открывают карточку-сводку —
  serif-значок W, заголовок статьи, короткое описание и лид-extract. Формулы из
  extract'а сохраняются: они приезжают SVG-рендером Wikimedia и вставляются в
  карточку инлайном, поэтому берут цвет её текста в любой палитре.
- **Блог Go**-ссылки (`go.dev/blog/<slug>`, легаси `blog.golang.org/<slug>`
  нормализуется к нему) открывают карточку с курсивным значком *Go*, заголовком
  поста, байлайном (дата локализуется) и зачином.
- **Документация go.dev** — `/doc/`, `/ref/`, `/wiki/`, `/security/` — открывает
  карточку той же семьи: раздел кикером (GO DOCS / GO REFERENCE / GO WIKI / GO
  SECURITY), заголовок страницы, подзаголовок, если он есть (спека и модель
  памяти датируют себя именно там), и первые абзацы. Ссылка внутрь раздела
  (`/ref/spec#Method_declarations`) показывает карточку страницы, и все якоря в
  одну страницу делят один фетч. Маркетинговые страницы (`/learn/`,
  `/solutions/`) и тур остаются обычными внешними ссылками.
- **GitHub** — issue и pull request (`github.com/<owner>/<repo>/issues/<n>`,
  `…/pull/<n>`, а также короткие ссылки Go-проекта `go.dev/issue/<n>` и
  `golang.org/issue/<n>`, ведущие в `golang/go`) открывают карточку из API
  GitHub: в шапке `owner/repo` и номер, дальше заголовок, статус в цветах GitHub
  (открыт, закрыт, не будет сделано, дубликат; у PR — открыт, черновик, влит,
  закрыт) с датой закрытия или слияния, автор, дата открытия, число комментариев
  и веха, до трёх меток, начало описания, прогресс подзадач и три главные
  реакции. Ссылка на отдельный комментарий (`#issuecomment-…`) показывает
  карточку всего треда. Два прочтения — только для `golang/*`: путь пакета из
  заголовка (`cmd/compile: …`) выносится моноширинной строкой над ним, префикс
  `proposal:` убирается, а у пропозала видна стадия — на рассмотрении,
  финальное обсуждение, отложен, принят, отклонён. Её дают метки `Proposal-*` и
  причина закрытия.

Каждая внешняя ссылка получает значок-классификатор: ↗ куда-то в веб,
✈ твой Telegram, ▶ твой YouTube, W Wikipedia, *Go* go.dev (и блог, и доки),
знак GitHub любая ссылка на `github.com` (и `go.dev/issue/<n>`, которая туда
ведёт). Репозиторий или файл исходника получают значок без карточки.
Внутренние ссылки — без значка.
В хроме компонентов (шапка fold, подпись callout, CTA-карточка) значок гасится,
чтобы не дублировать собственную иконку компонента — карточка по ховеру там
работает, глушится только сам значок. Ссылка со значком не отпускает последнее
слово — и сам значок — переноситься на новую строку в одиночку; фраза подлиннее
по-прежнему ломается по своим пробелам.

Фича **выключена** на тач-устройствах (тап обязан вести по ссылке) и уважает
`prefers-reduced-motion` (только fade, без шиммера).

## Физика ховера

Ритм общий с терм-карточками: **250 мс** намерения до открытия (`OPEN_DELAY`
в `term.js` использует то же значение — случайный проезд курсора ничего не
открывает), **120 мс** грейса на закрытие с перепроверкой `:hover`, и
«тёплое» окно ~450 мс после закрытия, в котором следующая карточка
открывается почти сразу. Вокруг поповера — невидимый **ореол 10 px**, ровно в
тот зазор, который он мостит: доводит курсор до ссылки-якоря и прощает промахи
у краёв (терм-карточки остаются на временно́м грейсе — их `overflow:hidden`
клипает любой ореол). Карточки следуют за скроллом и ресайзом и закрываются по
Escape.

**Карточка никогда не накрывает свою ссылку.** Она открывается *снизу*; если
снизу места нет — *сверху*; вместо того чтобы срываться с оси из-за пары
пикселей, допускает подрез до 80 px; дальше открывается *сбоку* — справа, а если
справа не влезает, слева. Когда не влезает нигде, карточка ужимается в ту
сторону, где места больше: тело скроллится (или сильнее усекается), голова и
строка действия сохраняют высоту; пол сжатия — 240 px. Ниже пола карточка просто
свешивается за край окна — вниз, чтобы терялась строка действия, а не заголовок.
Ступень выбирается один раз на открытие и держится до закрытия: скролл двигает
карточку, но не пересматривает решение; ресайз — пересматривает.

## Как включить

```toml
[params.linkPreviews]
  enable = true          # по умолчанию выключено
  budgetWords = 1400     # сколько статьи показывать в превью, целыми H2

[params.telegram]
  channels = ["your_handle"]   # ТВОИ каналы — их посты t.me получают карточку
```

Внутренние превью отдаются как **вторичный output-формат** — голый фрагмент по
адресу `/<slug>/index.preview.html`. Тема объявляет формат `preview` и включает
его для `page` и `section`. **Если на сайте задан свой `[outputs]`**, Hugo
перекрывает этот ключ карты поэлементно (не дополняет), поэтому `preview` нужно
повторить там:

```toml
[outputs]
  page    = ["html", "preview"]
  section = ["html", "preview"]   # для карточек-оглавлений серий
  # home / taxonomy / term превью не нужен
```

Пост t.me из канала, которого **нет** в `telegram.channels`, получает только
значок ✈, без карточки. Любая ссылка `youtube.com/watch` или `youtu.be` получает
карточку.

Карточкам GitHub настройка не нужна, но сайту, где их много, нужен токен. API
отвечает **60 запросам в час без авторизации** с одного IP, и холодная сборка с
бóльшим числом ссылок на GitHub теряет остальные карточки (молча, как любой
упавший фетч). Положи токен в окружение сборки:

```sh
HUGO_GITHUB_TOKEN=github_pat_… hugo
```

Подойдёт любой токен (fine-grained без единого разрешения читает публичные
репозитории), лимит станет 5000. Имя переменной обязано начинаться с `HUGO_`:
политика безопасности Hugo по умолчанию даёт шаблонам читать только такие (и
`CI`), поэтому `GITHUB_TOKEN` теме не виден.

## Что тянется на билде

Карточки Telegram и YouTube собираются через `resources.GetRemote` во время
сборки — из браузера в t.me/YouTube **не** ходит ничего (у t.me и так закрыт
CORS). Билд:

- парсит `t.me/<ch>` (имя, подписчики, описание, аватар) и
  `t.me/<ch>/<id>?embed=1` (текст, фото, просмотры, дата, реплай, реакции,
  кастомные эмодзи), скачивая всё медиа — CDN-URL телеги живут с истекающими
  токенами;
- читает инлайн-`videoDetails` со страницы YouTube (без API-ключа) и качает
  превью-кадр (`maxresdefault`, фолбэк `mqdefault`);
- берёт официальный REST-JSON сводки Wikipedia
  (`<lang>.wikipedia.org/api/rest_v1/page/summary/<title>?redirect=true`) — тот
  же эндпоинт, что у собственных превью Википедии, так что карточка читается из
  готового JSON. Текст берётся из `extract_html`, а **не** из простого
  `extract`: простой выбрасывает все формулы и оставляет дыры посреди фразы.
  Каждая формула в нём — SVG-рендер Wikimedia; он скачивается и вставляется в
  карточку инлайном: MathJax рисует их с `fill="currentColor"`, поэтому формула
  берёт цвет текста карточки в любой палитре, без инверсий под каждую тему. Если
  хоть одна формула не скачалась, карточка целиком откатывается на простой текст.
  **Wikimedia требует описательный `User-Agent`**, иначе отвечает `403`; тема
  шлёт его, собирая из `baseURL`. Кириллические тайтлы percent-энкодятся. Текст
  под **CC BY-SA** — атрибуцию несёт сама карточка, ссылаясь на статью. Страница
  типа `disambiguation` или без extract карточки не даёт (ссылка остаётся обычной
  внешней со значком W), а длинное автогенерённое `description` (частое на
  ru.wikipedia) отбрасывается, чтобы не дублировать extract.
- парсит страницу поста **блога Go**: заголовок (первый `<h1>` без класса),
  байлайн `<p class="author">` (авторы + дата, дата локализуется под язык
  страницы) и зачин из контейнера `<div class='markdown'>` — верхнеуровневые
  блоки до первого `<h2>`, а если пост начинается сразу с `<h2>` — блоки после
  него. Нет `<h1>` (или фетч упал) → карточки нет, ссылка остаётся внешней со
  значком *Go*.
- парсит страницу **документации go.dev**: первый `<h1>` внутри
  `<main id="main-content">`, `<h2 class="subtitle">`, если он есть, и первые три
  абзаца после заголовка — именно абзацы, а не «всё до первого `<h2>`»: половина
  этих страниц открывается сразу с `<h2>Introduction</h2>`, и правило блога
  вернуло бы пустоту. Абзацы короче 40 символов пропускаются (столько занимают
  обратные ссылки вроде «Back to Go Security»). Деградация та же: нет `<h1>` →
  нет карточки.
- запрашивает у REST API **GitHub** сам issue
  (`api.github.com/repos/<owner>/<repo>/issues/<n>`, он отвечает и за pull
  request) с `Accept: application/vnd.github.full+json`, который добавляет
  `body_html`, рендер описания самим GitHub. Зачин режется из него целыми
  верхнеуровневыми блоками: шаблонный хвост issue Go-проекта (разделы «Go
  version» и «go env», старые вопросы «воспроизводится ли / какая ОС») уходит
  вместе с содержимым, таблицы, `<details>` и картинки пропускаются, остальные
  заголовки разделов остаются маленькими подписями, а срез — три блока или ~600
  символов. Аватар автора скачивается, как любая картинка карточек. 404, 403 от
  лимита или сетевая ошибка → карточки нет, у ссылки остаётся значок GitHub.

Запросы кэшируются через `partialCached` по URL — каждый пост/видео тянется
**один раз** за билд, а Hugo кэширует ответы на диск между сборками — без срока
годности (`caches.getresource.maxAge = -1`), поэтому локальная сборка
показывает тот статус issue, какой был при первом фетче. `hugo --ignoreCache`
тянет заново, чистая сборка в CI — всегда.

### Деградации (билд никогда не падает)

Каждый запрос обёрнут так, что сетевая ошибка или недоступный ресурс приводят к
деградации, а не к падению сборки — **офлайн-билд всё равно проходит**:

- пост t.me, который не спарсился (удалён, приватный или создан после последнего
  билда) → **карточка канала** (аватар, имя, подписчики, описание);
- канал, который не удалось получить → минимальная карточка, всё ещё называющая
  канал;
- страница YouTube без `videoDetails` → **без карточки**, ссылка остаётся обычной
  внешней;
- кастомный эмодзи, чей арт не скачался → показывается его юникод-глиф.

Раз карточки печёт билд, счётчики поста и статус issue освежаются каждым
деплоем, а единственная дыра — пост, созданный после последней сборки — закрыта
карточкой канала.

## Что показывает превью статьи

Фрагмент превью несёт *всю* статью, нарезанную на разделы. JS показывает зачин и
целые H2-разделы, пока суммарный текст не достигнет `budgetWords` (минимум один
раздел), затем перечисляет оставшиеся H2 под «дальше в статье». Интерактив
нейтрализуется на билде, чтобы превью осталось тихим окном для чтения:

- фигура `{{</* widget */>}}` → карточка-плейсхолдер (⚙ + подпись);
- codapi-сниппет → блок кода `<pre>` остаётся, за ним тихий бейдж «запускается в
  статье»;
- любые `<script>` / `<style>` / `<iframe>` во фрагменте → вырезаются.

Callout'ы, fold'ы, таблицы и картинки остаются как есть.

## Область

Превью получают только ссылки в тексте статьи; оглавление, сноски, мост серии и
рельсы исключены. Ссылка на текущую страницу не превьюится.
